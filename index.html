Pixel Mage

Music videos with an AI agent as creative director
Role
Sole developer
Status
Nine finished videos. The AWS deployment is offline for now
Built with
PythonAnthropic SDKlibrosaKlingVeoAWSTerraform

A music-video system for artists. Give it a track and a direction. A Claude agent plans the video and calls a set of tools to produce it.

Human approval and budget limits

The agent never approves its own work. It acts only through thirteen fixed tools, stops at five checkpoints for the artist’s answer, and any tool that would go over budget refuses and tells it to ask.

  • The tool loop is written by hand on the Anthropic SDK, so every call can be checked and the run is saved every ten calls.
  • librosa finds the beats and section changes so cuts land on the music, and a fifteen-cut storyboard keeps characters consistent.

Infrastructure

AWS deployment

Pixel Mage ran at pixelmage.ai on AWS. Every piece below is defined in Terraform, and the same code also runs locally with no AWS account.

RequestsRoute 53DNS for the domain→CloudFrontCDN, caches assets for a year→Load balancerHTTPS, health checks→API on FargateFastAPI in a container
Render jobsAPI on Fargatequeues the job→SQSwork queue plus a dead-letter queue→Worker on Fargaterenders and keeps its lease→S3 and DynamoDBartifacts, jobs, users, run state
Around itECRimages scanned on pushSecrets Managermodel and OAuth keysIAMa role for each taskCloudWatch30 days of logsACMthe domain’s certificate
  • Eighteen Terraform files define it all, from DNS and the certificate to the task definitions and IAM roles.
  • One container image runs as both the API and the render worker, each with its own command.
  • A render can take many minutes, so the worker extends its SQS lease every five minutes. A job that fails three times goes to a dead-letter queue.
  • The worker runs as a single task on purpose. Two workers could write the same run’s state, so scaling out waits for a DynamoDB conditional claim.
  • deploy.sh runs the tests, pushes the image to ECR and rolls the services. One flag scales everything to zero when it isn’t in use.
  • The artifact bucket blocks public access and deletes run files after 90 days. The DynamoDB tables bill per request.

Nexus Habitat

An AI video factory that runs its own channels
Role
Sole developer
Status
Working system, 131 films in its library
Built with
PythonClaudexAI imagesElevenLabsffmpeg

A local video factory for story channels. Give it one sentence, or let a channel pitch its own next episode, and it produces a finished, narrated short film with music, a thumbnail and upload details.

Recipes, not agent code

Creative work happens in a lab session and is saved as a channel recipe, which is plain data. Production only ever runs recipes, never freshly written agent code, so a new idea can’t break a working pipeline.

  • Each channel runs Off, Propose or Auto. In Propose it pitches episodes from its own history, and I approve each one before it builds on schedule.
  • Every paid build sits behind limits. Channels start Off, each has a daily cap set by its cadence, one scheduled build runs at a time, and one button pauses everything.
  • An agent grades every finished episode on nine criteria, I rate it too, and a taste ledger tracks how far its grades sit from mine.

Project Moongate

An online world and the engine under it
Role
Sole developer
Status
In active development
Built with
C# serverGodot clientPython world tools

An original online RPG in the spirit of Ultima Online. Every coastline, road, building and dungeon is generated from a seed, and a custom C# server streams the world to a Godot client.

Testing inside every building

Towns connected on the map, but fences and furniture still blocked some shops. I reverted the change and added checks that walk into each building.

  • Automated checks catch what screenshots don’t reveal, including unreachable interiors and a wall standing nine metres into the air.
  • One registry owns every packet id and shared number, and the build fails when the docs and the code disagree.
1,356 commitsincl. an Unreal client experiment
The eight systems underneath
i

Backend & wire protocol

Authoritative C# server with a versioned binary protocol. Every packet id lives in one registry.

ii

World generation

Continents from a seed, with relief, water, towns, roads, and route-checked reachability down to building interiors.

iii

Procedural architecture

Houses, walls, castles, cloisters, ruins and dungeons from rule sets, with interiors you can walk.

iv

Spell VFX

A procedural effects pipeline for charge, projectile and impact, tuned by eye in a live harness.

v

Combat systems

Melee, ranged and spells on one geometry, with skillshot targeting, predicted projectiles and hit feedback.

vi

Client & rendering

Godot client with chunk streaming, 600 m of terrain relief, swimming and traversal.

vii

Asset pipeline

Local generative 3D (ComfyUI + Hunyuan3D) feeding props into the world under one art bible.

viii

Tooling & QA

One-command test battery and headless probes. The build fails when docs and code disagree.

Internal tool, runs on site

NetOps Console

One screen for a whole site network, with a live map, the device tree, alerts merged with the controller’s own events, and a standing audit.

How it works
  • Selecting any device shows its path from the internet, its ports, and what goes down with it.
  • Every reading goes to SQLite with a timestamp, so a problem can be traced after the fact.
  • No third-party dependencies. Three files, using Python’s standard library.
  • A demo mode runs a made-up site through the same alert rules, which is what the screenshot shows.
In daily use by my team

PM Tool

A self-hosted project board for a small team, with shared tasks, protected deadlines and team knowledge in one place.

How it works
  • Claude turns pasted meeting notes into assigned, dated tasks and drafts the weekly digest.
  • Ask “@ai what’s overdue?” in team chat and it reads the same tasks you do.
  • One FastAPI file over SQLite and a plain JavaScript front end, with no build step.
Working prototype, runs locally

SayViz

Business intelligence from a plain-English question. It builds the data model and documents every measure, then draws the dashboard. Its first test run built 7 dashboards from 3 raw CSV files in about three minutes.

How it works
  • DuckDB and Polars keep large files fast on a laptop.
  • Only anonymized summaries go to the model (Grok, or Ollama fully offline), so the raw data never leaves the machine.
  • Change one measure and only what depends on it recomputes.
Runs locally

VideoStumble

Type any topic, or none, and discover a video you might not have searched for.

How it works
  • A store of 7,667 videos sorted into 56,748 topics.
  • Serving is deliberately simple, using topic match, quality and whether you’ve seen it. The AI curates and tags, but it doesn’t rank.
  • Promoted videos must pass quality checks and stay below 8% of stumbles.

Viral Video Analyzer

Takes a short video apart, down to every scene cut, the words with timestamps, what’s on screen, and how the characters and story develop. The result is a structured brief a video model like Sora 2 can follow.

How it works
  • Whisper for word-level transcripts, plus automatic scene detection.
  • Gemini Vision by default, with OpenAI as a drop-in.
  • Writes JSON for machines and plain text for people.
